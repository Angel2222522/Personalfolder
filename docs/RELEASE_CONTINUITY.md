# Release continuity policy

## Απαράβατος κανόνας

Κάθε νέο APK του Personal Folder πρέπει να αποτελεί **ενημέρωση της ίδιας ήδη εγκατεστημένης εφαρμογής** και όχι ξεχωριστή/ασύμβατη εγκατάσταση.

Η συμβατότητα αναβάθμισης και η διατήρηση των δεδομένων είναι release-blocking απαιτήσεις. Αν δεν μπορούν να αποδειχθούν, το APK δεν θεωρείται έτοιμο για παράδοση.

## Υποχρεωτικές απαιτήσεις για κάθε μελλοντική έκδοση

1. **Ίδιο applicationId**
   - Το release applicationId παραμένει `com.angel.personalfolder`.
   - Δεν αλλάζει package/application identity για κανονικές εκδόσεις.

2. **Ίδια υπογραφή με την προηγούμενη εγκατεστημένη έκδοση**
   - Κάθε APK που προορίζεται για ενημέρωση πρέπει να υπογράφεται με το **ίδιο signing key / certificate** με την αμέσως προηγούμενη έκδοση που έχει εγκαταστήσει ο χρήστης.
   - Δεν επιτρέπεται να παραδίδεται ως update APK με νέο, προσωρινό ή τυχαίο debug key.
   - Το ιδιωτικό signing key **δεν αποθηκεύεται στο δημόσιο repository**. Πρέπει να διατηρείται εκτός Git και να παρέχεται με ασφαλή μηχανισμό (π.χ. GitHub Actions secrets ή άλλο ασφαλές signing environment).
   - Αν το σωστό signing material δεν είναι διαθέσιμο, η διαδικασία release πρέπει να σταματά πριν την παράδοση APK και να αναφέρεται καθαρά ότι δεν μπορεί να παραχθεί συμβατή ενημέρωση.

3. **Μονοτονικά αυξανόμενο versionCode**
   - Κάθε νέα έκδοση αυξάνει το `versionCode`.
   - Δεν μειώνεται και δεν επαναχρησιμοποιείται παλαιότερο `versionCode`.

4. **Καμία απώλεια δεδομένων κατά την αναβάθμιση**
   - Οι αλλαγές στη Room database γίνονται μόνο με ρητές migrations που διατηρούν τα υπάρχοντα δεδομένα.
   - Απαγορεύεται destructive migration / διαγραφή βάσης ως λύση αναβάθμισης.
   - Δεν αλλάζουν αυθαίρετα paths, file names, encryption assumptions ή identifiers που θα έκαναν τα ήδη αποθηκευμένα έγγραφα μη αναγνώσιμα.
   - Δεν θεωρείται αποδεκτή διαδικασία ενημέρωσης το uninstall/reinstall, επειδή αυτό μπορεί να διαγράψει app-private δεδομένα.

5. **Backward-compatible storage και encryption**
   - Κάθε αλλαγή σε schema, serialization, backup format, encrypted document format ή metadata πρέπει να προβλέπει migration/compatibility με την προηγούμενη εγκατεστημένη έκδοση.
   - Τα ήδη αποθηκευμένα έγγραφα, OCR, metadata, cases, relations, checklist, timeline και reminders πρέπει να παραμένουν προσβάσιμα μετά την ενημέρωση.

6. **Υποχρεωτικός έλεγχος upgrade path πριν από release**
   Πριν θεωρηθεί έτοιμο οποιοδήποτε APK για παράδοση πρέπει να επιβεβαιώνονται τουλάχιστον:
   - ίδιο release `applicationId`,
   - μεγαλύτερο `versionCode`,
   - ίδιο signing certificate με το προηγούμενο release,
   - επιτυχής migration της βάσης χωρίς απώλεια rows/relations,
   - πρόσβαση σε ήδη αποθηκευμένα και κρυπτογραφημένα αρχεία μετά την αναβάθμιση,
   - διατήρηση βασικών ρυθμίσεων και λειτουργικών δεδομένων όπου αυτό είναι τεχνικά αναμενόμενο.

## Release rule

**Δεν παραδίδεται νέο APK ως κανονική έκδοση του Personal Folder αν δεν μπορεί να εγκατασταθεί πάνω από την προηγούμενη έκδοση και να κρατήσει τα υπάρχοντα δεδομένα.**

Debug APK με διαφορετικό applicationId ή διαφορετική υπογραφή επιτρέπεται μόνο για απομονωμένες δοκιμές και πρέπει να επισημαίνεται ρητά ως μη συμβατό με in-place update.
